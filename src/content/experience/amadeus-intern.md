### Specification Repair Tool

<ul class="tech-list" aria-label="Skills">
<li class="chip">Webscraping</li><li class="chip">HTML</li><li class="chip">Python</li><li class="chip">UI</li><li class="chip">REST API</li><li class="chip">Selenium</li>

#### Context

A tool was needed to repair an outdated customer specification containing thousands of HTML documents containing several broken hyperlinks. Doing this by hand would take hundreds of man-hours. The tool was written with Python and used a certain REST API to access and update the documents. An automated Selenium browser was also used to allow the user to view the documents and the changes made to them in real time.

It was to be used by non-developers, so it was designed to be as user-friendly as possible. As the tool had to account for human error (in the form of typos and mismatched names), several techniques such as fuzzy matching were incorporated to ensure that the tool could repair as many links as possible. In the event the tool was not able to automatically resolve a link, the user was given the option to manually resolve the link themselves. Backups were also kept to ensure easy reversal.

The tool also used a proprietary update system to ensure that the tool was always up-to-date with the latest version, and to allow for easy updates in the future.

### Java Code Analyser

<ul class="tech-list" aria-label="Skills">
<li class="chip">Java</li><li class="chip">Code Parsing</li><li class="chip">Python</li><li class="chip">UI</li><li class="chip">Automation</li>
</ul>

#### Context

A tool was needed to analyse a Java product to extract and tabulate hundreds of tables of information that were crucial to the end user. These tables are usually generated by non-developers who are not familiar with Java, meaning they were sometimes blocked by needing to wait for a developer to aid them, and so it was designed to be as user-friendly as possible.

#### Implementation

As the tool was analysing a codebase written by other employees, it had to account for inconsistencies in the codebase. For example, crucial files were placed in slightly different locations, and so a lot of techniques were used to mitigate this.

Again, a combination of Regex and proprietary techniques were used to extract the information from the codebase, and the tool was designed to be as modular as possible to allow for easy expansion in the future. The tool also had a more refined version of the update feature used in the Specification Repair Tool.
